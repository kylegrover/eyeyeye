A class-shuffle model

A candidate mechanism, not a recovered cipher. It can produce shared openings, isomorphs and changes followed by matching output. No key has been found that reproduces all nine messages.

Read a position, then shuffle

  1. Start each message with the same deck of 83 cards, numbered 0 to 82.
  2. Give every plaintext letter a different, fixed position in the deck.
  3. Output the card at the letter's position.
  4. Apply a fixed shuffle chosen by the letter's class. Letters in the same class use the same shuffle.

This is a shared-shuffle version of extended group autokey. See Lymm's formalization and FrobtheBuilder's field notes. The key changes with the plaintext, as in an autokey cipher; here the changes are permutations. The working variant has no extra movement of the card just read.

What is assumed

Two levels of plaintext correspondence are used on these pages:

  • R: at repeat-supported positions of a selected isomorph, corresponding cells in the two passages hold the same plaintext letter. It is a claim across copies, not just within each row.
  • W: corresponding cells throughout the selected span hold the same plaintext, including positions whose symbols occur only once there.

W implies R on that span. These are hypotheses about selected passages, not a rule that every coincidental isomorph must be shared text. Other conditions still matter: the model here uses one shared initial deck, fixed read positions, and the same letter-to-shuffle rule in every message. Cell 0 is left outside encryption.

In notation

Dt          the deck before letter t, a bijection from positions to cards
r(a)        the position letter a reads; different letters, different positions
κ(a)        the class of letter a, one of 1 … K
P1 … PK     the shuffles, fixed permutations of 83 positions

ct = Dt[ r(at) ]                  read
Dt+1[i] = Dt[ Pκ(at)(i) ]          shuffle

The key is (D0, r, κ, P1 … PK). With one shuffle, put Q = D0 P1 D0−1: this is the shuffle expressed on symbols rather than positions. Equal letters at a shift of d then give a symbol map Qd, independent of the start of the passage. The three-copy certificate contradicts K = 1 under R.

E1 and W1 differ at cells 25–28, match at 29–32, differ at 33–36, then match again. In this model, replacing a letter with another of the same class changes its output but leaves the next deck unchanged. That is one explanation. Equal outputs alone do not establish equal deck states: different states can agree at the positions subsequently read, and different updates can cancel.

A double is a property of a letter pair

a followed by b produces equal symbols ⇔ Pκ(a)(r(b)) = r(a)

The current deck cancels out of this condition. For a fixed key, every occurrence of the same letter pair has the same outcome. Treating all 1,018 observed adjacencies as independent 1/83 trials therefore overstates the evidence from zero doubles.

A simulation of 400 random keys and English game-text samples at the nine body lengths used 27 plaintext symbols and three randomly assigned classes. It produced a mean of 11.4 doubles, but zero doubles in 4.8% of trials. This is a model-dependent comparison, not a p-value for every possible plaintext. Recorded output.

A key deliberately preventing doubles for every possible plaintext is a stronger condition than these messages require. In particular, the absence of doubles here does not by itself prove that the plaintext alphabet has fewer than 83 letters.

What remains open

Two to four shuffle classes are the current working range, not a proved upper bound. Unrelated shuffles and small changes to a common base both remain candidates. If whole passages correspond, the E4/E5 break requires a relative change moving at least six symbols; it does not identify the individual shuffles.

Some variants also move the card just read—a “lift”—before or after the class shuffle. The checks below concern the simpler no-lift model and do not exclude those variants. The alphabet, spacing, letter classes and reason for 83 cards are still unknown.

Rejecting a guess is easier than verifying one

A crib is a guessed stretch of plaintext. Folding closure tracks the possible positions of each card through the guessed text: equal read letters must use the same position, and each shuffle must be a one-to-one map. A contradiction rejects that guess under the specified model. No contradiction does not guarantee that a complete 83-card key exists.

For a reproducible solution, supply the alphabet, initial deck, read positions, class map and shuffles, then encrypt the proposed text back to all nine messages. A solver timeout is neither confirmation nor rejection. Crib checking is one route; recovering a key recipe or other external information could identify the text without starting from a crib.
